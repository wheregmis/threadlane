# Fusion mode enhancement research

**Scope.** This is a documentation-only comparison of the current repository implementation with Cognition's [Devin Fusion article](https://cognition.com/blog/devin-fusion) (article display date **06.29.26**, chart update shown as **8/7/2026**). The article's numbers and operating claims below are reported vendor claims, not Threadlane measurements or commitments.

## Executive assessment

Threadlane already has the right control-plane shape: a frontier main that owns planning/ambiguity/final review, a cheaper sidekick model, prompt triage, durable child lanes, failure escalation, and model changes at compaction. That is meaningful Fusion scaffolding, not merely a prompt template. The important qualification is narrower than “no cache accounting”: Threadlane records usage including cache-read/cache-write fields, and the OpenAI adapter parses provider-reported cached-token details; it also sends provider cache-key fields where supported. Those are generic usage/provider capabilities, not yet Fusion-correlated cost, cache, or episode metrics, and they do not prove provider cache retention, cache TTL, or zero incremental inference cost.

The largest gaps versus the article's design are (1) keyword triage rather than a measured/dynamic classifier, (2) a single sidekick choice rather than explicit mid-session model routing based on quality/cost signals, (3) no first-class Fusion correlation across existing usage, cache, lane, latency, pricing, and outcome data, and (4) limited evidence that a recovered or restarted session preserves the complete Fusion router state rather than only the durable conversation and lane journal. Enhance the existing orchestrator, harness, events, and model-role paths; do not add a parallel orchestration subsystem or new lane architecture.

## What the article says, and how to interpret it

The article describes a frontier agent that delegates and monitors minimally while retaining plan, ambiguity, and final review; two capable agents with independent persistent cached contexts; dynamic classifiers that can escalate and switch models mid-session; switching at compaction to avoid an additional cache miss (not zero inference cost); provider-specific cache expiry (often about five minutes); and examples where slow tests and mechanical deprecations save cost, while a judgment-heavy React feature lost intent (reported score -27). It reports up to 60% cost reduction (initially 35%), 41% for Fable, and 88% of internal merged PRs fully automated by updated routing. These are vendor-reported results, not independently verified results for Threadlane; treat them as hypotheses for evaluation, not unsupported Threadlane targets or acceptance evidence.

## Prioritized enhancements

### P0 — Make the current contract measurable and durable

1. **Add a Fusion decision/episode correlation schema using existing events and harness journal.** Do not recreate usage accounting: join existing `RuntimeUsage`/`TokenUsage` records (including provider-reported cache-read/cache-write fields) to session/run/lane IDs, route reason, classifier version, active/target model, compaction generation, latency, outcome, and provider/model pricing metadata when available. Extend `FusionUpdate` or an adjacent structured event and persist the minimum audit fields through the existing harness journal next to lane completion. Do not synthesize cache hits or prices when a provider/catalog does not report them.
   *Acceptance:* every arm, delegation, sidekick completion/failure, compaction switch, and escalation has a correlated record; a session replay can distinguish “policy switched at compaction” from “provider cache hit”; unsupported provider fields and unavailable pricing are null/unknown, not zero.

2. **Persist and restore router state safely.** Reuse harness facts/session metadata (the existing model and session-plan restoration path is in `crates/threadlane-coding-agent/src/runtime.rs:594-617`) to store a versioned Fusion state: models, counters, error streak, classifier version, and last compaction generation. Restore only after validating model/config compatibility; reset stale in-flight streaks conservatively. Keep append-only lane journal semantics.
   *Acceptance:* kill/restart tests preserve completed-lane accounting and do not lose an escalation; a torn write cannot select an unvalidated model; legacy sessions still open with Fusion disabled or a documented default.

### P1 — Improve routing without pretending the classifier is magic

3. **Introduce a versioned classifier interface behind the existing `evaluate_fusion_prompt`.** Keep the keyword classifier as the deterministic baseline and add an optional classifier result with confidence, reason codes, and `abstain`. Route low-confidence or judgment-risk prompts to main; record the decision before work starts. Use labeled repository tasks (mechanical deprecations/tests versus intent-heavy features) and require an offline confusion matrix before enabling a new policy.
   *Acceptance:* deterministic fallback works offline; classifier timeout/error never blocks or silently delegates; golden tests cover false-mechanical cases; route/version/confidence are visible in telemetry.

4. **Add explicit mid-session escalation signals.** Keep the existing two-failure threshold as a safety fallback, but allow structured signals from verification failure, unresolved question, permission/tool failure, or main review to request escalation. Route only at a safe turn/compaction boundary, and require the main to acknowledge the sidekick result before declaring completion.
   *Acceptance:* a judgment-risk signal switches ownership at the next safe boundary; no duplicate lane commit; the final event links the reviewed lane outcomes and unresolved questions.

5. **Model provider cache reality explicitly.** Add a provider capability/telemetry interface for cache support, TTL, cache key/context identity, and reported hit/miss. Keep switching-at-compaction as a scheduling optimization, but remove “free” wording from user-facing status unless the provider confirms the relevant cache behavior.
   *Acceptance:* providers without cache support continue correctly; a TTL expiry causes no incorrect reuse; tests verify that a switch is scheduled at compaction but inference/token cost remains separately counted.

### P2 — Optimize after safety and measurement

6. **Replace the binary fast-model choice with a constrained model policy.** Reuse `model_roles`/provider credential refresh and project settings, adding explicit allowed models and budget/quality limits only after telemetry exists. Choose among configured models using task class, provider availability, observed latency/cost, and cache capability; never route secrets or protected work solely on price.
   *Acceptance:* policy decisions are explainable and reproducible from recorded inputs; unavailable/unauthorized models fall back to main; per-model cost and quality can be compared.

7. **Make existing same-lane revival intentional, not assumed.** Reuse `revive_subagent_lane`/`resume_subagent_lane` for follow-up work on a settled lane so history remains continuous; add only the durable generation/lease and invalidation checks needed for safe reuse (compaction, workspace change, TTL expiry, or failed recovery). Do not introduce a parallel lane architecture or claim persistent provider cache from the journal alone.
   *Acceptance:* a revived lane cannot read another task's context; stale or failed revivals recover safely; isolation and restart tests pass; cache savings are reported only from provider evidence.

## Phased rollout and evaluation

* **Phase 0 (instrument, no behavior change):** land Fusion correlation fields in existing events/journal, use existing provider-reported token/cache fields, and add restart/compaction/failed-lane fixtures. Establish a baseline split by task class: cost per successful task, wall time, retries, tool failures, human/main interventions, and review defects.
* **Phase 1 (guarded policy):** enable versioned classifier behind a project/session flag; preserve keyword fallback, main-on-abstain, two-failure escalation, and a kill switch. Sample or review judgment-heavy routes. Compare against a non-Fusion control with the same models where possible.
* **Phase 2 (adaptive routing):** add structured quality signals and compaction-boundary model selection. Roll out by repository/project cohort, with automatic rollback on defect, escalation, latency, or spend regressions.
* **Phase 3 (optional cache/lane optimization):** only after provider evidence and isolation tests, evaluate provider-specific TTL-aware switching and safe reuse through the existing same-lane revival path.

Evaluate vendor claims as hypotheses, not goals that justify quality loss. Report median and tail cost/latency, successful-task rate, rework/rollback rate, human intervention, escalation rate, cache-hit rate by provider, and intent-preservation review scores. Stratify mechanical, mixed, and judgment-heavy tasks; a blended “savings” number can hide the exact React-feature failure mode described by Cognition. Compare matched controls and publish confidence intervals/sample sizes. Do not state a Threadlane percentage reduction until these measurements exist.

## Risks and non-goals

* **Intent loss:** keyword routing can mistake a feature with mechanical wording for safe delegation. Main-on-abstain, explicit questions, review evidence, and judgment-task holdouts are required.
* **False cache economics:** compaction avoids an additional application decision point, but provider cache expiry, invalidation, and inference charges remain provider-specific. No zero-cost or 60% claim is implied.
* **Durability/isolation:** journal persistence is not provider cache persistence. Version state, validate model changes, and keep lane context isolated across restart/recovery.
* **Cost/latency regressions:** extra delegation, summaries, reviews, and failed sidekick attempts can outweigh cheap model pricing. Measure total episode cost, not model price alone.
* **Security and permissions:** cheaper routing must not bypass the existing tool/permission/session workspace guards. No new privilege or secret-sharing path is proposed.
* **Non-goals:** do not rewrite the provider layer, introduce a second session store, force all prompts through a classifier, promise provider cache semantics Threadlane cannot observe, or optimize for vendor-reported percentages before local quality and cost evidence.
